# Подсветка синтаксиса QSP для Obsidian

[English](README.md) | Русский

Подсветка блоков кода `qsp` в [Obsidian](https://obsidian.md): в режиме чтения и в редакторе. Плагин подсвечивает синтаксис, но не выполняет QSP-код и не проверяет его корректность.

## Установка

Текущий релиз: **2.0.0**.

1. Скачайте `qsp-syntax-obsidian.zip` из [последнего релиза](https://github.com/AleksVersus/qsp-syntax-obsidian/releases/latest), а не архив **Source code**, автоматически создаваемый GitHub.
2. Извлеките папку `qsp-syntax-obsidian` в каталог `.obsidian/plugins/` вашего хранилища.
3. Убедитесь, что непосредственно в `.obsidian/plugins/qsp-syntax-obsidian/` находятся `main.js`, `manifest.json` и `styles.css`, без лишней вложенной папки. При обновлении замените эти файлы файлами из одного и того же релиза.
4. Перезагрузите Obsidian. Откройте **Settings → Community plugins** (Настройки → Сторонние плагины) и при необходимости разрешите использование сторонних плагинов.
5. В списке установленных плагинов включите **QSP-syntax highlighting**.

## Использование

Проверьте работу синтаксиса на этом фрагменте кода:

````plain
```qsp
local $top_text = $args[0] & ! text from top
local $command = $iif($args[1]<>"", $args[1], "*pl") & ! command for print text
local $screen = $mid($args[1], 1, 1) & ! first symbol from command
local $text = ""
if $screen="*":
  ! if fist symbol is *
  ! main description wondow
  $text=$maintxt
else
  ! addition description window
  $text=$stattxt
end
! use dynamic for run command:
dynamic "
  <<$screen>>clr
  <<$command>> $args[0]
  <<$screen>>p $args[1]
", $top_text, $text
```
````

## Поддерживаемая подсветка

- Обычные и многострочные комментарии, включая комментарии после `:` и поясняющий текст после `END`.
- Заголовки и окончания локаций, метки, ключевые слова, встроенные функции, пользовательские вызовы и системные переменные с префиксами типов.
- Идентификаторы с Unicode, числа, операторы, знаки пунктуации, строки и экранирование удвоением кавычек.
- Ограниченное распознавание блоков кода, кортежей и интерполяции `<< ... >>`, включая `>>` внутри поддерживаемых строковых литералов с противоположным типом кавычек.

## Ограничения и отображение

- После `#` в заголовке локации нужен пробел или табуляция: используйте `# room`, а не `#room`. Компактные формы остаются кодом.
- Плагин не проверяет синтаксис и типы. Рекурсивные конструкции распознаются приближённо; произвольная вложенность, полная подсветка многострочных и незавершённых меток, а также экранированные литералы с тем же типом кавычек внутри интерполяции не поддерживаются.
- Для `_` нет отдельной подсветки маркера продолжения строки. Поля записей сохраняют обычную подсветку переменных и пунктуации; `?` подсвечивается как число.
- В Live Preview неактивные QSP-блоки могут отображаться как виджеты предпросмотра с кнопкой редактирования, в отличие от обычных строк редактора.
- Сообщалось о лишней пустой строке или строке с отступом над QSP-виджетом внутри списка. Проблема ещё не воспроизведена независимо и не исправлена.

Если подсветка не появилась, перезагрузите плагин или заметку либо отредактируйте блок кода. При проблеме [создайте issue](https://github.com/AleksVersus/qsp-syntax-obsidian/issues): приложите минимальный воспроизводящий пример **Markdown** с отступами списка и границами блока, версии Obsidian и плагина, режим просмотра, тему и скриншот.

## Разработка

Используйте Node.js 24 и установку зависимостей из lock-файла:

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

`npm test` запускает 887 проверок сканера и 1886 проверок с настоящим Prism. Для 33 браузерных проверок диапазонов нужен отдельный стенд из [CONTEXT.md](CONTEXT.md); Node-тесты не проверяют весь интерфейс Obsidian. Сборка создаёт `main.js`; поместите его вместе с `manifest.json` и `styles.css` в тестовое хранилище и перезагрузите плагин.
